Счета за обучение Cohort создаёт автоматически, раз в сутки ночью, по биллинговой политике вашего центра. Большинство счетов, которые кажутся пропавшими или неверными, — это политика, работающая так, как она настроена, поэтому начните с неё.

## Проверьте биллинговую политику

В боковом меню выберите **Биллинговая политика**. По умолчанию её видят владелец, администратор и менеджер. Настройки, от которых зависит, когда появляется счёт и на какую сумму:

| Настройка | Что она определяет |
| --- | --- |
| **Режим биллинга** | **Предоплата — счёт заранее**: счёт в начале каждого периода. **Постоплата — счёт по факту**: счёт после окончания месяца, за прошедший месяц. |
| **Цикл биллинга** | **Календарный месяц**: всем выставляют счета каждый месяц начиная с числа из поля **День биллинга**. **Годовщина зачисления**: каждому ученику выставляют счёт в то число месяца, когда он начал заниматься, например с 12 июля по 11 августа, затем с 12 августа по 11 сентября. |
| **Начисление при зачислении** | Выставляется ли первый счёт только что зачисленного ученика сразу или при следующем ночном запуске. |
| **Пропорция по умолчанию** | Сколько платит за первый месяц ученик, который пришёл в середине календарного месяца. |
| **Правило учёта** | Для тарифных планов с оплатой за занятие: какие занятия оплачиваются. |

Эти настройки нельзя изменить самостоятельно. Чтобы изменить их, обратитесь в поддержку Cohort. Изменение вступает в силу со следующего ночного запуска и никогда не меняет уже выставленные счета.

## Счёт не появился

<AccordionGroup>
  <Accordion title="Срок ещё не наступил">
    - **Календарный месяц**: счета появляются каждый месяц начиная с числа из поля **День биллинга**.
    - **Годовщина зачисления**: следующий счёт появится в день, когда начнётся следующий цикл ученика.
    - **Постоплата — счёт по факту**: счёт за месяц появится после его окончания, начиная с числа из поля **День биллинга** следующего месяца.
  </Accordion>

  <Accordion title="Ученика зачислили недавно">
    Если **Начисление при зачислении** выключено, первый счёт появится после следующего ночного запуска, а не в момент зачисления. Если дата начала зачисления в будущем, до этой даты ничего не начисляется.
  </Accordion>

  <Accordion title="Зачисление не активно">
    Cohort выставляет счета только по активным зачислениям. Ученику, зачисление которого было приостановлено весь расчётный период, счёт за этот период не выставляется. После отчисления ученика Cohort перестаёт выставлять ему счета: в режиме **Постоплата — счёт по факту** последний неполный месяц выставляется в момент отчисления. Проверьте вкладку **Зачисления** ученика.
  </Accordion>

  <Accordion title="Тарифный план курса — за занятие">
    По тарифному плану **За занятие** счёт выставляется после окончания месяца за занятия, учтённые по правилу из поля **Правило учёта**. Если ни одно занятие не учтено, счёта нет. Отменённые занятия не оплачиваются никогда.

    Такие счета Cohort создаёт автоматически, только когда **Режим биллинга** — **Постоплата — счёт по факту**. При режиме **Предоплата — счёт заранее** обратитесь в поддержку Cohort или [создайте счета вручную](/ru/admin/invoices/create-an-invoice).
  </Accordion>

  <Accordion title="Счёт аннулирован">
    Cohort не создаёт замену аннулированному автоматическому счёту. Чтобы выставить счёт за этот период, [создайте его вручную](/ru/admin/invoices/create-an-invoice).
  </Accordion>

  <Accordion title="Счёт есть, но вы его не находите">
    - Список **Счета** может быть отфильтрован. Нажмите **Сбросить фильтры**.
    - В карточке ученика на вкладке **Счета** показаны все его счета.
    - Если ученик говорит, что не видит счёт, проверьте его статус. Счёт в статусе **Черновик** не виден ученику, пока его не выставят: см. [Выставление счёта](/ru/admin/invoices/issue-an-invoice).
  </Accordion>
</AccordionGroup>

## Сумма выглядит неверной

<AccordionGroup>
  <Accordion title="Первый счёт меньше тарифного плана">
    При цикле **Календарный месяц** ученик, пришедший в середине месяца, платит только за ту часть, которую посещает, по правилу из поля **Пропорция по умолчанию**. В конце описания позиции указана начисленная доля, например «(prorated 8/12)»: 8 из 12 занятий месяца или дней.

    При цикле **Годовщина зачисления** первый счёт так никогда не уменьшается: каждый цикл полный.
  </Accordion>

  <Accordion title="Меньше по другой причине">
    - Постоянная скидка на зачислении ученика автоматически применяется к каждому счёту, который Cohort создаёт по этому зачислению. См. [Назначение постоянной скидки](/ru/admin/students/standing-discount).
    - Если включено **Автоприменение средств кошелька**, деньги из кошелька ученика сразу идут в оплату. **Итого** не меняется, но в строке **Оплачено** видна эта сумма, а **Остаток** меньше. См. [Кошелёк ученика](/ru/admin/students/student-wallet).
  </Accordion>

  <Accordion title="Больше тарифного плана">
    Если в биллинговой политике включены **Пени за просрочку**, Cohort добавляет к просроченному счёту позицию с пеней. См. [Как выставляются счета](/ru/admin/invoices/how-invoicing-works).
  </Accordion>

  <Accordion title="Неожиданная сумма счёта за занятия">
    Сумма равна числу учтённых занятий, умноженному на цену одного занятия по плану. Какие занятия учитываются, зависит от поля **Правило учёта**: **Посещённые + без уважит. причины**, **Все запланированные** или **Только посещённые**.
  </Accordion>

  <Accordion title="В счёте старая цена">
    Каждый счёт сохраняет цену тарифного плана на момент создания счёта. После изменения цены плана новая цена применяется только к новым счетам.
  </Accordion>
</AccordionGroup>

## Исправьте счёт

Позиции выставленного счёта изменить нельзя. Вместо этого:

- Чтобы уменьшить сумму, [выпустите кредит-ноту](/ru/admin/invoices/issue-a-credit-note) на разницу или [примените скидку](/ru/admin/invoices/apply-a-discount).
- Чтобы полностью заменить счёт, [аннулируйте его](/ru/admin/invoices/void-an-invoice) и [создайте правильный вручную](/ru/admin/invoices/create-an-invoice).

По умолчанию это могут сделать владелец и администратор.

<Warning>
  Аннулирование необратимо, и Cohort не создаст автоматический счёт за этот период заново. Создайте замену сами.
</Warning>
